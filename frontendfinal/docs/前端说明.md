```

│   ├── auth-api.ts            用户与系统管理接口
│   ├── item-api.ts            物品接口（含审核台与总览）
│   ├── claim-api.ts           认领申请接口
│   ├── announcement-api.ts    公告接口
│   └── upload-api.ts          图片上传
├── components/                界面组件（kebab-case 文件名与标签）
├── composables/
│   ├── use-paged-records.ts   「加载更多」式分页取数

├── router/index.ts            路由表 + 守卫（requiresAuth / requiresBackOffice / requiresSystemAdmin / requiresGuest）
├── stores/user.ts             会话 store：凭证 + 档案的唯一持有者
├── styles/
│   ├── tokens.css             设计令牌（颜色、圆角、阴影、间距、排版、动效）
│   └── base.css               重置 + 排版 + 手写界面原语（按钮 / 输入 / 标签 / 卡片 / 骨架屏 / 浮层）
├── types/                     api / user / item / claim / announcement
├── utils/                     归一化、校承、日期、错误文案、本地存储、401 事件
└── views/                     页面
mock/api-mock-server.mjs       本地联调用的 mock 后端（零依赖）
```

数据流只有一条：**页面 → store / composable → api → http → 后端**。页面不直接调用 axios，也不直接读写 localStorage。

## 3. 命名约定

作业「共同要求」里写了组件 kebab-case、变量 camelCase，落实口径如下：

- 变量、函数、常量、store 状态、storage 键值、路由 `name` 一律**小驼峰**：`feedPageSize`、`loadNextPage`、`applyQuery`、`buildPagedResult`、`authTokenStorageKey`。
- 命名要求能当句子读：`refreshProfile`、`establishProfile`、`describePagination`，不出现 `data1`、`tmp`、`res` 这类缩写。
- 组件文件名与模板标签 **kebab-case**：`item-card.vue`、`<admin-item-row>`。
- PascalCase 仅用于 TS 类型 / 接口 / 枚举（`ItemRecord`、`ApiRequestOptions`、`ItemStatus`）与 Vue 内置标签。
- 唯一例外保留 Vue 脚手架惯例：`App.vue` 与 `main.ts` 中的 `import App`。大小写重命名在 macOS 与 Linux 上行为不同，会牵动队友分支，故未改动。

## 4. 设计系统

目标观感是**简洁、现代**，参照对象是 Apple 的产品页。据此**没有引入 Element Plus**：

- 它的默认视觉语言（紧凑控件、`#409EFF` 高饱和蓝、4px 圆角、带边框的表单盒子）与「大留白 + 大圆角 + 单色灰阶 + 单一强调色 + 毛玻璃」这套目标相反，用上就要为每个组件打一层覆盖样式，改动量比自持一层更大；
- 本项目需要的控件不多（按钮、输入、标签、卡片、骨架屏、浮层、分段控件），手写一层换来确定性的观感，代码量与维护成本都可控；
- 产物体积差别明显：手写这一层后主包 **118 kB**（gzip 约 45 kB），整包 508 kB；沿用组件库整包会到 860 kB 量级。

具体落在 `styles/tokens.css`（令牌）与 `styles/base.css`（原语）：

| 维度 | 取值 |
|---|---|
| 字体 | `-apple-system / SF Pro Text / PingFang SC` 系统字栈，标题带 `-0.02em` 字距 |
| 灰阶 | `#1d1d1f` / `#6e6e73` / `#86868b` / `#f5f5f7` |
| 强调色 | `#0071e3`，仅用于主行动点与链接 |
| 圆角 | 药丸 980px、卡片 22px、控件 16px |
| 阴影 | 低对比大扩散（`0 4px 24px rgba(0,0,0,.06)`），悬停才加深 |
| 动效 | `cubic-bezier(0.32,0.72,0,1)`，180–320ms；`prefers-reduced-motion` 下全部关闭 |

顶栏与筛选条用 `backdrop-filter: saturate(180%) blur(20px)` 做吸顶毛玻璃；信息流卡片悬停上浮 4px 并轻微放大图片。键盘可达性用 `:focus-visible` 焦点环，骨架屏与卡片同尺寸以免加载完成时布局跳动。

## 5. 关键约定

**请求封装**
- 所有请求经 `api/http.ts`；`{code,msg,data}` 中 `code !== 0`（`200` 也视为成功）一律抛 `ApiError`。
- 错误归四类：`business`（业务 code）、`http`（4xx/5xx，优先用后端 `msg`，否则按状态码给文案）、`timeout`、`network`。
- 两个开关：`skipAuth`（登录、注册、公开列表不注入 `Authorization`）、`silent`（不弹全局提示，由页面用内联文案展示；`silent` 不吞异常，promise 依旧 reject）。
- 后端用 4xx/5xx 承载业务错误码时，按业务错误处理并优先取其 `msg`。

**401 / 会话失效矩阵**
- 非静默请求遇 HTTP 401 或业务码 2 → 广播 `lostFound:authExpired`；`App.vue` 收到后清空凭证、提示一次、跳登录页并带上 `redirect`。
- 静默请求 → 完全忽略，绝不触发退出登录。
- `skipAuth` 请求的 401（如登录密码错误）→ 按普通业务错误处理，只做内联提示。
- `api/http.ts` 只负责广播，不引用 store 与 router，避免请求层反向依赖业务层形成循环引用。

**登录顺序（易错点）**
- 拿到凭证后**先写入 localStorage 再取档案**。`Authorization` 由请求层每次从 localStorage 读取注入，顺序颠倒会让取档案那一步变成匿名请求而拿到 401。
- 凭证换不来档案时回滚会话，不留半登录状态。

**分页口径**
- 接口的分页响应只给记录数组、不给总数，故「是否还有下一页」按「本页条数是否装满 `page_size`」推断（`utils/paged-result.ts`），空页也视为末页。后端若补上 `total`，只需改这一个函数。
- 信息流每页 12 条，靠 `IntersectionObserver` 哨兵在距底部 500px 时自动续页；哨兵在「加载中 / 已到末页」期间禁用，并在加载结束后补一次判断，否则滚动会卡住。

**筛选条件放在 URL 上**
- 信息流的分类与关键词写回 `?category=&keyword=`，刷新或把链接发给同学都能还原同一视图；浏览器前进后退也会同步回本地状态。

**表单提交**
- 每个提交动作都有独立的 `isSubmitting` 单飞锁，提交中禁用按钮并显示 loading。
- 提交失败在卡片内用内联文案呈现（对应请求传 `silent`），不在全局重复弹出。
- 校验规则集中在 `utils/validators.ts`，返回错误文案字符串（空串即通过），页面按字段拼装 `errors` 对象，便于单测直接断言。

**表单数据边界**
- 前端模型是 camelCase，接口字段是下划线。转换只在 `api/*-api.ts` 与 `utils/*-normalizers.ts` 发生，页面只面对 camelCase。
- `PUT /api/items/{item_id}` 是**全量更新**，提交时把全部字段带上，未填的可选字段显式送空串而不是省略。

## 6. 后端契约中的不确定点（前端已做的兼容）

1. **登录响应的凭证位置。** 文档把 `POST /auth/login` 的 `data` 标为 `{ token }`，但后端定稿前不宜写死字段名。`utils/user-normalizers.ts` 按以下顺序探测：响应体 `token` / `access_token` / `accessToken` / `jwt` / `authorization` / `auth_token` → 嵌套容器 `user` / `userInfo` / `data` / `session` / `auth`（最多下钻 3 层，取「含 `username` 的那一层」作为档案）→ 响应头 `authorization` / `x-token` / `x-auth-token` / `token`（自动剥离 `Bearer ` 前缀）。
   - 都探测不到时按 Cookie 会话处理：继续调用 `GET /auth/profile` 验证会话。
   - 若档案也取不到，登录页明确提示「登录响应未返回登录凭证（token）」，不静默失败。
   - **后端定稿后建议固定一个字段名**，届时只需改 `user-normalizers.ts` 里的候选数组。
2. **用户 ID 字段名不统一。** 数据模型写 `user_id`，`GET /auth/profile` 的示例写 `id`。前端同时兼容两者，统一收敛为 `userId`。
3. **物品状态的字段名。** 列表与详情示例用 `item_status`，管理端查询参数与「管理物品状态」用 `status`。记录归一化时两者都认。
4. **驳回理由的传递方式未定义。** 「审核操作」的响应回传 `reject_reason` 却没有对应的请求参数字段。前端在驳回时随请求体提交 `{ reject_reason }`，通过时不带该字段。后端若不接收，审核动作本身不受影响。
5. **公告上下线没有独立接口。** 数据模型与「获取所有公告」都出现了「已下线」状态，但没有给出切换接口。前端在 `PUT /api/admin/announcements/{id}` 的请求体里附带 `announcement_status`（0 公开 / 1 下线）。若后端不接受该字段，这个动作会被忽略，标题与正文仍按原样提交。
6. **管理端列表接口的请求体。** 「获取待审核列表」「获取全部物品列表」「审核操作」等接口把 `{user_id, username, nickname, role, contact}` 列为请求体，那是鉴权中间件的上下文对象，不是前端该发的数据。前端只带 `Authorization` 头，不构造这个 body。
7. **列表响应只给数组、不给总数。** 见第 5 节「分页口径」。

## 8. 环境与运行

```bash
npm install

# 本地联调：先起 mock 后端，再起前端（开发代理默认指向 http://localhost:8080）
MOCK_PORT=8090 npm run mock:api
VITE_API_TARGET=http://localhost:8090 npm run dev

# 对接真实后端：只改环境变量，无需改代码
VITE_API_TARGET=http://<后端地址>:8080 npm run dev
```

- `vite.config.ts` 把 `/api` 代理到 `VITE_API_TARGET`（默认 `http://localhost:8080`，与后端 `SERVER_PORT` 默认值一致），开发态因此不受 CORS 影响；生产态由 Nginx 反向代理 `/api` 即可。
- `VITE_API_BASE` 可覆盖接口根地址（例如直连远端后端、绕过代理）。
- `vite.config.ts` 刻意保持对象式配置而非函数式，因为 `vitest.config.ts` 用 `mergeConfig` 合并它，函数式配置要先求值再合并，徒增一处易错点。
- mock 后端只用于联调自测，不属于交付代码：内存实现全部分组接口，含鉴权、角色校验、错误码与业务规则（重复认领返回 9、审核未发布帖返回 7、通过认领后自动驳回同物品其他申请等），并内置种子数据（物品 51 条含待审核与已驳回、认领、公告），图片用内联 SVG 占位以便离线渲染。

过程中修掉三个真实缺陷：

1. **登录后先取档案、后写凭证**，导致取档案那一步是匿名请求而拿到 401（提示「未登录或登录已过期」）。已改为凭证先落盘、失败回滚会话，并在 `stores/user.ts` 注明该顺序的原因。
2. **`fromDateTimeLocalValue` 丢掉分钟。** `'14:30'.split(':')` 的解构只取到了第一段（`'14'`），随后的长度判断把它回退成 `00:00`，于是表单里填的任何时分都会落库成整点零点 —— 不报错、不告警，界面上看不出异常，只有把真实提交的结果从服务端读回来才暴露；它还会连带影响按该字段倒序的信息流排序。已改为逐段取值、缺省才补零，并补上该方向的往返单测（此前只有反向的 `toDateTimeLocalValue` 有用例，正是这个缺口让它连过三轮）。
3. **图片上传的旧错误提示不会随成功上传清除。** 先投一张不支持的格式会显示提示，随后投合法图片上传成功，提示仍留在界面上，读起来像「这次也失败了」。已改为每次投递先清空上一轮的错误。
